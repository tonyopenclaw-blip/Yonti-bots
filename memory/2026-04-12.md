## NO Strategy Overhaul (Afternoon Session)

Tony repeated "No should work like yes" — meaning NO should mirror YES logic, not be a reversal play.

### Changes Made:
1. **candle_watcher.py**: NO signal now requires mid > $0.55 before emitting (market extended = NO cheap)
2. **superbot.py 12-min NO**: Guard changed from YES price check to NO price check directly
   - Old: `if yes_mid > 0.55: block` (wrong — $0.52 YES passes but NO is $0.48, not extended)
   - New: `if no_price > 0.55: block` (correct — NO must be cheap to enter)
3. **12-min pullback**: raised from 3% → 5% (3% is noise in pumps)
4. **Auth cache fix**: reduced kalshi_sdk.py `auth_cache_window` from 500ms → 50ms (fixes 401 replay rejection on rapid calls)

### How YES Works (for reference):
- Candle: 15-min candle spends >90% time above prev_close → bullish confirmation
- 12-min: coinbase price > prev_close at minute 12 → enter YES
- Entry guard: mid < $0.55 (only enter when market is cheap)
- Holds to settlement

### How NO Should Work (mirrored):
- Candle: 15-min candle spends >90% time below prev_close AND mid > $0.55
- 12-min: coinbase price < prev_close at minute 12 AND no_price < $0.55
- Entry guard: no_price < $0.55 (only enter when NO is cheap = market extended)
- Holds to settlement

### Auth 401 Debugging:
- Symptom: Bot gets 401 Unauthorized, direct API calls work
- Cause: Multiple rapid calls within 500ms produce identical auth headers → Kalshi rejects as replay
- Fix: `auth_cache_window = 50` in kalshi_sdk.py (class-level cache shared across instances)
